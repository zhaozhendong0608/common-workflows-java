# 自动归档系统使用指南

本指南说明如何使用自动归档系统将会话内容归档到项目。

---

## 🎯 核心价值

在工作流执行过程中，会话中会产生大量有价值的内容：
- 💬 技术选型讨论
- 📄 SQL 变更脚本
- 🔧 代码实现片段
- 💡 问题解决方案

**自动归档系统**帮你**一键提取**这些内容并**自动保存**到项目的正确位置。

---

## 🚀 快速开始（3 步骤）

### Step 1: 保存会话内容

在对话结束后，复制整个会话内容到文件：

```bash
# 方法 1: 手动复制粘贴
# 复制整个对话内容，保存为 session.log

# 方法 2: 使用 Hermes 导出（如果支持）
hermes session export > session.log
```

---

### Step 2: 运行归档脚本

```bash
cd /path/to/your-project
python /path/to/common-workflows-java/scripts/auto-archive.py

### Step 3: 审查并提交

```bash

## 📂 归档位置说明

### 自动归档的目录结构

```
your-project/
├── project-kernel/
│   ├── db/
│   │   └── migrations/           # SQL 脚本
│   │       └── V{timestamp}__*.sql
│   ├── 03_决策日志/              # ADR 草稿
│   │   └── ADR-{num}-*.md
│   └── snippets/                 # 代码片段
│       └── {timestamp}_{lang}_snippet.{ext}
└── docs/
    └── session_summary_*.md      # 会话摘要
```

### 各目录的作用

#### 1. project-kernel/db/migrations/
**存储**: SQL 变更脚本

**文件名格式**: `V{yyyymmdd_HHMMSS}__session_migration_{序号}.sql`

**示例**:
```
V20260623_143000__session_migration_1.sql
V20260623_143001__session_migration_2.sql
```

**内容示例**:
```sql
-- Migration from session
-- Generated: 2026-06-23 14:30:00
-- Context: 讨论添加用户邮箱索引...

CREATE INDEX idx_user_email ON user(email);
```

---

#### 2. project-kernel/03_决策日志/
**存储**: 技术决策记录（ADR 草稿）

**文件名格式**: `ADR-{编号}-会话讨论_{date}.md`

**示例**:
```
ADR-006-会话讨论_2026-06-23.md
```

**内容**: 自动生成的 ADR 草稿（**需要人工完善**）

**重要**: 这是草稿，必须手工编辑完善后才能使用！

---

#### 3. project-kernel/snippets/
**存储**: 代码片段

**文件名格式**: `{timestamp}_{language}_snippet.{ext}`

**示例**:
```
20260623_143000_java_snippet.java
20260623_143001_python_snippet.py
```

**内容**: 会话中的代码片段 + 上下文注释

---

#### 4. docs/
**存储**: 会话摘要

**文件名格式**: `session_summary_{timestamp}.md`

**示例**:
```
session_summary_20260623_143000.md
```

**内容**: 统计信息、归档位置、后续操作

---

## 🔍 识别规则说明

### SQL 脚本识别
**规则**: 匹配 ` ```sql ... ``` ` 代码块

**示例**:
````markdown
```sql
CREATE INDEX idx_email ON user(email);
```
````

---

### 技术讨论识别
**关键词**:
- "选择.*(?:而不是|vs|对比)"
- "为什么.*(?:采用|使用)"
- "技术选型"
- "方案.*(?:对比|选择)"
- "ADR"

**示例**:
```
为什么选择 Redis 而不是 Memcached？
技术选型：MyBatis vs JPA
方案对比：串行查询 vs 批量查询
```

---

### 代码片段识别
**支持语言**:
- Java (```java)
- Python (```python)
- JavaScript (```javascript 或 ```js)
- Bash (```bash 或 ```sh)

**过滤规则**: 只保存 ≥ 3 行的代码片段

## ⚠️ 注意事项

### 1. ADR 草稿需要人工完善
自动生成的 ADR 只是草稿，包含：
- ✅ 讨论的上下文
- ❌ 完整的决策内容（需要补充）
- ❌ 详细的理由和后果（需要补充）

**必须手工编辑完善后才能作为正式 ADR！**

---

### 2. 检查 SQL 脚本的正确性
自动提取的 SQL 可能：
- ⚠️ 缺少上下文
- ⚠️ 包含测试代码
- ⚠️ 需要调整

**建议**: 手动审查每个 SQL 脚本，确认后再执行

---

### 3. 代码片段仅供参考
自动提取的代码片段：
- ℹ️ 可能不完整
- ℹ️ 可能有上下文依赖
- ℹ️ 适合作为参考，不建议直接使用
