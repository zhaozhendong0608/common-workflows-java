# 业务测试

**命令**: `/test`

---

## 输入

- 代码变更（来自 `/execute`）
- 测试计划（根据流程类型）

---

## 测试类型

### 🟢 精简流程（ACK-LITE）
- 单元测试（已在 `/execute` 完成）
- **本步骤可跳过**

### 🟡 标准流程（ACK）
- API 集成测试（100% 自动化）
- 核心业务场景验证

### 🔴 完整流程（ACK-FULL）
- API 集成测试
- E2E 端到端测试（80% 自动化）
- UI/UX 人工测试清单

---

## 核心步骤

### 1. API 集成测试

```bash
# 启动测试环境
mvn spring-boot:run -Dspring.profiles.active=test

# 运行 API 测试
mvn verify -Dtest=*ApiTest
```

**验证清单**:
- [ ] 正常场景：200 OK
- [ ] 参数校验：400 Bad Request
- [ ] 权限校验：403 Forbidden
- [ ] 异常处理：500 Internal Server Error
- [ ] 响应格式：符合 API 规范

---

### 2. E2E 端到端测试（完整流程）

```bash
# 使用 Selenium/Cypress 等工具
npm run e2e:test
```

**测试场景**:
- [ ] 用户登录 → 操作 → 查看结果
- [ ] 数据流转：前端 → 后端 → 数据库 → 前端
- [ ] 异常恢复：网络中断、超时等

---

### 3. UI/UX 人工测试（完整流程）

**测试清单**:
- [ ] 页面布局正常
- [ ] 按钮响应正确
- [ ] 错误提示友好
- [ ] 表单验证有效
- [ ] 数据展示准确
