# 04_质量关卡 (Quality Gate V2.1)

> **定位**: 验证已实现功能的架构合理性。
> **目的**: 识别"技术债"，并对 Solid 资产变更进行深度审计。
> **V2.1升级**: 集成度量指标审查（KVC/SCV 阈值检查）

## Node A: Evidence 审计 (Evidence Audit)

检查 `03_受控执行` 的输出：
1. **证据完整性**: 是否包含 `Run/Scan/Diff/Context_Log`？
2. **Solid 审计**:
 * 若触碰 `Strict` 资产，是否提供了 `Approval_Hash`？
 * 若触碰 `Regulated` 资产，是否提供了 `ADR_Entry`？
 * **ADR 合规性**: 检查 `project-kernel/03_决策日志 (ADR).md` 中对应条目是否已登记
3. **约束检查** ← 新增:
 * P0 约束是否通过？（来自 03_受控执行 的 Constraint_Check）
 * P1 警告是否可接受？
4. **熵增探测**:
 * 复杂度检查: 是否引入 > 3 层嵌套或上帝类？
 * 命名规范: 是否有 Chinglish 或无意义变量名？

## Node A.5: 度量指标审查 (Metrics Review) ← 新增

检查 `05_度量分析` 的输出：

### 度量阈值检查

```markdown
### 度量指标审查

#### KVC 检查
- 当前值: [从度量报告获取]
- 阈值: >= 0.90
- 状态: ✅ 达标 / ❌ 未达标

如果未达标:
 - 返回 03_受控执行 修正违规
 - 禁止进入 Node B (全量回归)

#### SCV 检查
- 当前值: [从度量报告获取]
- 阈值: < 5.0
- 状态: ✅ 正常 / ⚠️ 突变

如果突变 (SCV >= 5.0):
 - 人工判断: 是否合理？
 - 建议: 考虑重构或拆分方法
 - 可继续流程，但记录技术债

#### 综合判断
- KVC 未达标 → **强制返工** (P0 约束)
- SCV 突变 → **建议重构** (P1 建议)
```

## Node B: 全量回归 (Regression)

**仅当触碰 Solid 资产时执行**:
> "执行项目核心测试套件 (`Core Test Suite`)，确保本次变更未破坏系统底座。输出 Regression 报告摘要。"

**执行命令**:
```bash
# 运行完整测试套件
mvn clean test

# 或针对性测试
mvn test -Dtest=*IntegrationTest
```

## Node C: 决策点 (Decision Point)

向用户汇报：
> "指挥官，质量关卡审查结束。
> * Evidence 评分: [S/A/B/C]
> * 度量指标: [KVC: X.XX / SCV: X.X] ← 新增
> * Solid 违规: [无/有]
> * ADR 回扣: [Pass/Fail]
>
> 请输入 **ACK** 确认无风险，或 **NACK** 要求补充证据。"

### 决策标准

```markdown
### 质量关卡通过标准

#### 必须满足（强制）
- [ ] Evidence Block 完整
- [ ] P0 约束全部通过
- [ ] KVC >= 0.90
- [ ] Solid 资产有 ADR/Approval
- [ ] 核心测试通过

#### 建议满足（可豁免）
- [ ] SCV < 5.0
- [ ] P1 警告数量 < 3
- [ ] 代码风格统一

#### 通过判定
- 所有"必须满足"项通过 → **ACK** (进入 05_归档)
- 任一"必须满足"项失败 → **NACK** (返回 03_受控执行)
- "建议满足"项失败 → 记录技术债，可继续
```

## 使用技巧

### 快速度量检查

如果忘记执行 05_度量分析，可在此阶段快速检查：

```bash
# 快速 KVC 检查
echo "=== KVC 违规检查 ==="
grep -rn 'context\.put' src/main/java/... | grep -v '"node:' | wc -l

# 快速 SCV 检查
echo "=== 复杂度检查 ==="
lizard src/main/java/... | grep 'CCN' | awk '{if ($2 > 10) print}'
```

### 质量评分标准

**S 级**（优秀）:
- KVC = 1.0
- SCV < 2.0
- 0 个 P1 警告
- 代码风格完美

**A 级**（良好）:
- KVC >= 0.95
- SCV < 3.0
- P1 警告 < 2

**B 级**（合格）:
- KVC >= 0.90
- SCV < 5.0
- P1 警告 < 5

**C 级**（不合格）:
- KVC < 0.90 或 SCV >= 5.0
- 必须返工

## 常见问题

**Q: 度量指标不达标必须返工吗？**
A: KVC < 0.90 必须返工（P0 约束）。SCV >= 5.0 可以豁免，但要记录技术债。

**Q: 如何快速提高 KVC？**
A: 使用搜索替换批量修正 Context Key 格式。例如：
```bash
# 查找违规
grep -rl 'context\.put("' src/ | xargs sed -i '' 's/context\.put("\([^"]*\)",/context.put("node:\1",/g'
```

**Q: SCV 突变一定是坏事吗？**
A: 不一定。如果是新增必要的业务逻辑，复杂度上升是合理的。但如果是简单修改导致突变，就需要警惕。
