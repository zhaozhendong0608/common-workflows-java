## 自动归档脚本使用

### 快速开始

```bash
# 1. 保存会话内容到 session.log
# （复制整个对话内容）

# 2. 运行归档脚本
python scripts/auto-archive.py

# 3. 查看结果
ls .agent/metrics/
ls project-kernel/03_决策日志/
```

---

### 脚本功能

#### 1. SQL 脚本提取

**识别规则**: 
- 代码块标记为 `sql`
- 或包含关键词：`CREATE TABLE`, `ALTER TABLE`, `INSERT INTO`, `UPDATE`, `DELETE FROM`

**输出位置**: `project-kernel/db/migrations/`

**文件命名**: `V{timestamp}__{description}.sql`

**示例**:
```
输入（会话中）:
```sql
ALTER TABLE user ADD COLUMN email VARCHAR(255);
```

输出:
project-kernel/db/migrations/V20260623_143000__add_user_email.sql
```

---

#### 2. 技术讨论识别

**识别规则**:
- 包含技术关键词：决策、选型、架构、性能、优化、缓存、数据库等
- 对话长度 > 200 字
- 包含原因分析或方案对比

**输出位置**: `project-kernel/03_决策日志/`

**文件命名**: `ADR-{number}-会话讨论_{date}.md`（草稿）

**示例**:
```
输入（会话中）:
User: 为什么选择 Redis 而不是 Memcached？
AI: Redis 优势在于...

输出:
project-kernel/03_决策日志/ADR-006-会话讨论_2026-06-23.md
```

---

#### 3. 代码片段提取

**识别规则**:
- 代码块（非 SQL）
- 长度 > 10 行

**输出位置**: `project-kernel/snippets/`

**文件命名**: `snippet_{timestamp}_{language}.{ext}`

---

#### 4. 会话摘要生成

**输出位置**: `docs/session_summary_{timestamp}.md`

**内容**:
- 会话时间
- 主要任务
- 关键决策
- 生成的文件列表

---

## 手动归档方法

如果无法使用自动脚本，可以手动归档。

### 1. 记录 ADR

**模板位置**: `templates/adr-template.md`

**步骤**:
```bash
# 1. 复制模板
cp templates/adr-template.md project-kernel/03_决策日志/ADR-006-缓存方案选型.md

# 2. 编辑内容
vim project-kernel/03_决策日志/ADR-006-缓存方案选型.md

# 3. 填写内容
```

**ADR 必填项**:
- 编号和标题
- 日期和状态
- 背景（为什么需要这个决策）
- 决策（选择了什么方案）
- 后果（这个决策的影响）

---

### 2. 更新 FAQ

**位置**: `project-kernel/04_答疑库.md`

**格式**:
```markdown
### Q: 为什么选择 Caffeine 而不是 Redis？

**A**: 
- 本地缓存延迟更低（5ms vs 50ms）
- 数据量小（1万用户），无需分布式
- 运维成本更低，无需维护 Redis 集群

**相关**: ADR-006, CacheConfig.java

**添加时间**: 2026-06-23
```

---

### 3. 更新项目进度

**位置**: `project-kernel/05_项目进度.md`

**格式**:
```markdown
## 2026-06-23
- ✅ 完成用户导出功能
- ✅ 添加 Caffeine 缓存，性能提升 95%
- ⏳ 待优化：报表性能
- 🔴 待修复：分页显示bug
```

---

### 4. 保存度量数据

**位置**: `.agent/metrics/`

**步骤**:
```bash
# 复制度量报告
cp /tmp/metrics_report.md .agent/metrics/report_20260623_143000.md

# 追加到历史记录
echo "2026-06-23,CacheOptimization,0.93,2.6,PASS" >> .agent/metrics/history.csv
```

## ADR 编写指南

### ADR 结构

```markdown
# ADR-{编号}: {决策标题}

**日期**: 2026-06-23  
**状态**: 已接受 / 已弃用 / 已替代

---

## 背景

为什么需要做这个决策？遇到了什么问题？

（2-3段，说明问题的上下文）

---

## 决策

我们决定采用什么方案？

（明确的决策描述，1-2段）

---

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 方案A | ... | ... | ❌ 不采用 |
| 方案B | ... | ... | ✅ 采用 |

---

## 后果

### 正面影响
- 性能提升 95%
- 运维成本降低

### 负面影响
- 内存占用增加 50MB
- 需要学习新的 API

### 需要注意
- 缓存失效策略需要谨慎设计
- 定期监控缓存命中率

---

## 相关资源

- 代码: `src/main/java/com/example/cache/`
- 文档: `docs/cache-design.md`
- 测试: `src/test/java/com/example/cache/`
```

---

### ADR 编写技巧

1. **背景要充分**: 让未来的读者理解为什么做这个决策
2. **决策要明确**: 不要模棱两可，清楚说明选了什么方案
3. **后果要全面**: 正面、负面、注意事项都要写
4. **方案对比**: 最好有表格对比多个方案
5. **相关资源**: 链接到相关代码、文档、测试

### FAQ 示例

```markdown
### Q: 为什么查询性能突然变慢？

**A**: 
可能原因：
1. 缓存失效 - 检查缓存配置和TTL
2. 数据库慢查询 - 查看 slow query log
3. 索引缺失 - 检查 EXPLAIN 结果
4. 并发过高 - 查看连接池配置

排查步骤：
1. 查看监控指标（响应时间、缓存命中率）
2. 检查数据库慢查询日志
3. 分析 SQL EXPLAIN
4. 查看连接池使用情况

**相关**: 
- ADR-006: 缓存方案选型
- 文件: src/main/java/com/example/cache/CacheConfig.java
- 文档: docs/performance-tuning.md

**关键词**: 性能, 缓存, 数据库, 慢查询

**添加时间**: 2026-06-23
```

#### 手动完善 ADR

```markdown
# ADR-006: 采用 Caffeine 本地缓存优化查询性能

**日期**: 2026-06-23  
**状态**: 已接受

## 背景
用户查询接口响应时间达到 120ms，影响用户体验。
经分析，大部分查询都是重复的用户信息查询，适合引入缓存。

## 决策
采用 Caffeine 本地缓存，TTL 设置为 60 秒。

## 方案对比
| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Redis | 分布式、持久化 | 延迟 50ms、运维成本高 | ❌ |
| Caffeine | 延迟 <5ms、运维简单 | 不支持分布式 | ✅ |

## 后果
- ✅ 性能提升 95%（120ms → 5ms）
- ✅ 运维成本降低
- ⚠️ 内存占用增加 50MB
```

## 常见问题

### Q1: 自动归档脚本依赖什么？

**A**: 
- Python 3.7+
- 标准库（re, json, datetime 等）
- 无需额外依赖

### Q2: 如何自定义识别规则？

**A**: 
编辑 `scripts/auto-archive.py`，修改关键词列表：
```python
TECH_KEYWORDS = ['决策', '选型', '架构', '性能', '优化', ...]
```

### Q3: ADR 编号如何分配？

**A**: 
按顺序递增，脚本会自动检测最新编号并 +1。

### Q4: 归档后需要做什么？

**A**: 
1. 审查 ADR 草稿，补充完整信息
2. 验证 SQL 脚本的正确性
3. 提交到 Git
4. 通知团队成员
