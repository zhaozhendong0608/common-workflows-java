# 流程选择指南 (Quick Reference)

> **定位**: 快速决策工具，帮助你选择合适的开发流程
> **使用时机**: 在 `/03_需求雷达` 完成后，不确定走哪个流程时参考

---

## 一分钟决策树

```
开始
  ↓
是否修改 > 2 个文件？
  ├─ 否 ──→ 是否修改核心逻辑？
  │          ├─ 否 ──→ 🟢 精简流程 (ACK-LITE)
  │          └─ 是 ──→ 🟡 标准流程 (ACK)
  │
  └─ 是 ──→ 是否触碰 Solid 资产？
             ├─ 否 ──→ 🟡 标准流程 (ACK)
             └─ 是 ──→ 🔴 完整流程 (ACK-FULL)
```

## 三种流程对比

| 维度 | 🟢 精简流程<br>(ACK-LITE) | 🟡 标准流程<br>(ACK) | 🔴 完整流程<br>(ACK-FULL) |
|------|-------------------------|---------------------|------------------------|
| **预计时间** | 30 分钟 | 60 分钟 | 93 分钟 |
| **文件数量** | ≤ 2 | 3 - 5 | > 5 |
| **代码行数** | ≤ 50 | 51 - 150 | > 150 |
| **适用场景** | 改字段、加校验 | 新增功能、修改逻辑 | 重构模块、架构变更 |
| **Evidence** | 简化版 (5字段) | 标准版 (8字段) | 完整版 (20字段) |
| **度量分析** | ❌ 跳过 | ✅ KVC/SCV | ✅ KVC/SCV + 详细报告 |
| **业务测试** | ❌ 跳过 | ❌ 跳过 | ✅ API + E2E |
| **ADR 归档** | ❌ 跳过 | ❌ 跳过 | ✅ 必须 |

## 常见问题 (FAQ)

### Q1: 我能强制走完整流程吗？

**A**: 可以。输入 `OVERRIDE` 后手动指定流程步骤。

```
用户: OVERRIDE
AI: 请指定执行步骤 (例如: 01,02,03,04,05,07,08)
用户: 01,02,03,04,05,06,07,08
AI: 确认执行完整流程（含业务测试），预计 85 分钟
```

---

### Q2: 精简流程是否降低质量？

**A**: 不会。精简流程仍然保证：
- ✅ P0 约束检查（强制）
- ✅ 单元测试通过（必须）
- ✅ Evidence Block（简化但完整）
- ✅ 质量关卡（人工审查）

只是跳过了对小改动**性价比低**的步骤（度量分析、业务测试、ADR 归档）。

---

### Q3: 如何判断是否触碰 Solid 资产？

**Solid-Strict** (需 ADR + Approval_Hash):
- `pom.xml` / `build.gradle`
- `db/migration/`
- `.env` / `application.yml` (生产配置)
- `CI/CD` 配置
- `api/contracts/` (API 契约)

**Solid-Regulated** (需 ADR_Entry):
- 核心 Domain Model
- 安全模块 (Authentication/Authorization)
- 支付/订单核心逻辑

---

### Q4: 能否在执行过程中切换流程？

**A**: 不建议。流程类型应该在 `/03_需求雷达` 阶段确定。

如果执行中发现任务复杂度评估错误：
1. 立即停止当前执行
2. 返回 `/03_需求雷达` 重新评估
3. 选择正确的流程类型

## 最佳实践

### ✅ 建议做

1. **遵循 AI 建议**: AI 的分流评估基于客观指标，准确率高
2. **小改动走精简**: 不要为了"完美"而浪费时间
3. **大改动走完整**: 重要变更不要省流程
4. **定期复盘**: 每月统计各流程耗时，优化阈值

### ⚠️ 谨慎做

1. **频繁 OVERRIDE**: 说明评估体系需要调整
2. **所有任务走完整**: 说明团队对流程不信任
3. **所有任务走精简**: 说明质量标准太低

### ❌ 禁止做

1. **跳过 P0 约束检查**: 无论哪个流程，P0 必须检查
2. **跳过单元测试**: 无论哪个流程，测试必须通过
3. **跳过 Evidence Block**: 无论哪个流程，证据必须产出

## 附录：评分计算器

### 手动计算公式

```
综合得分 = (文件数得分 × 0.30)
         + (代码行数得分 × 0.25)
         + (Pizza切片得分 × 0.20)
         + (Solid触碰得分 × 0.15)
         + (风险等级得分 × 0.10)
```

### 示例计算

```
任务: 新增部门管理 CRUD
- 文件数: 4 → 得分 2 → 2 × 0.30 = 0.60
- 代码行数: 120 → 得分 2 → 2 × 0.25 = 0.50
- Pizza切片: 未触发 → 得分 0 → 0 × 0.20 = 0.00
- Solid触碰: 无 → 得分 0 → 0 × 0.15 = 0.00
- 风险等级: 中 → 得分 2 → 2 × 0.10 = 0.20

综合得分 = 0.60 + 0.50 + 0.00 + 0.00 + 0.20 = 1.30

结论: 1.30 ≤ 1.5 → 🟢 精简流程
```
