# 受控执行

**命令**: `/execute`

---

## 输入

- 需求分析报告（来自 `/radar`）
- 流程类型（ACK-LITE/ACK/ACK-FULL）
- 约束清单（如有，来自 `/constraint`）

---

## 核心步骤

1. **读取约束清单**（标准/完整流程）
   - 加载 `project-kernel/constraint-checklist.yml`

2. **编写代码**（遵守项目规约）
   - Jackson 序列化标准
   - 中文日志规范
   - 无魔法值
   - 异常处理规范
   - API 返回格式统一

3. **编写测试**
   - 精简流程: 单元测试
   - 标准流程: 单元测试 + API 测试
   - 完整流程: 单元测试 + 集成测试 + E2E 测试

4. **运行测试**
   ```bash
   mvn clean test
   ```

5. **输出 Evidence Block**（分级）

---

## 输出

- 代码变更
- 测试报告
- Evidence Block（分级：5/10/20字段）

---

## Evidence Block 分级

### 🟢 精简版（5字段）- ACK-LITE
- `Compliance_Status` - 合规状态
- `Target_Files` - 修改的文件列表
- `Test_Run` - 测试执行证据
- `Constraints_Checked` - 约束检查清单
- `Summary` - 一句话总结

### 🟡 标准版（10字段）- ACK
精简版 5 字段 +
- `Changes_Summary` - 变更摘要
- `Constraint_Checklist_Status` - 约束清单完成度
- `API_Test_Evidence` - API 测试证据
- `KVC_Preview` - KVC 预估值
- `SCV_Preview` - SCV 预估值

### 🔴 完整版（20字段）- ACK-FULL
标准版 10 字段 +
- `Architecture_Impact` - 架构影响
- `Performance_Impact` - 性能影响
- `Dependencies_Added` - 新增依赖
- `KVC_Before/After` - KVC 变化
- `SCV_Before/After` - SCV 变化
- `Rollback_Plan` - 回滚计划
- `ADR_Required` - 是否需要记录 ADR
- ... (更多字段)
