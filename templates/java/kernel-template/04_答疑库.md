## 开发问题

### Q3: MyBatis 查询返回 null 怎么办？

**A**: 常见原因和解决方案

**原因 1: resultType 配置错误**
```xml
<!-- ❌ 错误 -->
<select id="getUserById" resultType="User">
  SELECT user_id, user_name FROM user WHERE id = #{id}
</select>

<!-- ✅ 正确：字段名与属性名不匹配时使用 resultMap -->
<resultMap id="UserMap" type="User">
  <id column="user_id" property="userId"/>
  <result column="user_name" property="userName"/>
</resultMap>

<select id="getUserById" resultMap="UserMap">
  SELECT user_id, user_name FROM user WHERE id = #{id}
</select>
```

**原因 2: SQL 语句错误**
```java
// 打印实际执行的 SQL
log.debug("Executing SQL: {}", sql);
```

### Q5: 事务不生效怎么办？

**A**: 检查以下几点

**1. 是否添加 @Transactional 注解**
```java
@Service
public class UserService {
    @Transactional  // ← 必须添加
    public void createUser(User user) {
        // ...
    }
}
```

**2. 是否在同一个类内部调用**
```java
// ❌ 错误：同类内部调用，事务不生效
@Service
public class UserService {
    public void methodA() {
        this.methodB();  // 事务不生效
    }
    
    @Transactional
    public void methodB() {
        // ...
    }
}

// ✅ 正确：通过 Spring 代理调用
@Service
public class UserService {
    @Autowired
    private UserService self;  // 注入自己
    
    public void methodA() {
        self.methodB();  // 事务生效
    }
    
    @Transactional
    public void methodB() {
        // ...
    }
}
```

## 性能问题

### Q6: 查询很慢怎么优化？

**A**: 按以下步骤排查

**1. 检查是否有索引**
```sql
-- 查看执行计划
EXPLAIN SELECT * FROM user WHERE username = 'test';

-- 如果 type = ALL（全表扫描），需要加索引
CREATE INDEX idx_username ON user(username);
```

**2. 检查是否查询了不必要的字段**
```java
// ❌ 错误：查询所有字段
SELECT * FROM user;

// ✅ 正确：只查询需要的字段
SELECT id, username, email FROM user;
```

**3. 考虑使用缓存**
```java
@Cacheable(value = "user", key = "#id")
public User getUserById(Long id) {
    return userMapper.selectById(id);
}
```

### Q7: TDB 查询 26 万条数据很慢？

**A**: 这是正常的，优化方案：

**1. 使用 Caffeine 缓存（推荐）**
```java
@Cacheable(value = "tdb-data", key = "#deviceId + '-' + #startTime", 
           cacheManager = "caffeineCacheManager")
public List<DataPoint> getHistoryData(Long deviceId, Date startTime) {
    // 查询 TDB
}
```

**配置**:
```yaml
caffeine:
  cache:
    maximumSize: 100
    expireAfterWrite: 60s
```

**2. 分页查询**
```java
// 每次只查询 1000 条
List<DataPoint> data = queryWithPagination(deviceId, startTime, 1000);
```

### Q9: 生产环境 OOM 怎么办？

**A**: 调整 JVM 参数


```bash

# 生成堆转储
jmap -dump:format=b,file=heap.hprof <pid>
```

## 业务问题

### Q10: 为什么算子节点使用 shape 而不是 type？

**A**: 历史原因和设计决策

**背景**:
- 系统早期使用 `data.type` 字段
- 后期重构改为 `shape` 字段（kebab-case 格式）
- 保留了两个字段以兼容旧数据

**使用规范**:
```javascript
// ✅ 正确：使用 shape 判断
if (node.shape === 'time-offset') {
    // 时间偏移算子
}

// ❌ 错误：不要使用 data.type
if (node.data.type === 'TimeOffset') {
    // 可能不准确
}
```

**可评价算子清单**:
- `time-offset` - 时间偏移
- `time-interval` - 时间间隔
- `switch-statistics` - 开关量统计
- `analog-max` / `analog-min` / `analog-avg` - 模拟量最值/平均

### Q11: JS 大整数精度丢失怎么办？

**A**: Long 型 ID 在前端会丢失精度

**问题**:
```javascript
// 后端返回 Long 型 ID: 1234567890123456789
// 前端接收后变成: 1234567890123456800（精度丢失）
```

**原因**:
- JavaScript Number 最大安全整数：2^53 - 1
- 雪花算法生成的 ID 超过此范围

**解决方案**:
```java
// 后端：序列化为字符串
@JsonSerialize(using = ToStringSerializer.class)
private Long id;
```

```javascript
// 前端：使用字符串传递
const userId = '1234567890123456789';  // 字符串
```

```vue
// Vue Props 定义
props: {
  userId: [Number, String]  // 兼容两种类型
}
```
