# 质量关卡

**命令**: `/quality`

---

## 输入

- 代码变更（来自 `/execute`）
- 度量报告（来自 `/measure`，可选）
- 测试报告（来自 `/test`，可选）

---

## 核心步骤

### 1. 代码规范检查

- [ ] Jackson 序列化标准
- [ ] 中文日志规范
- [ ] 无魔法值
- [ ] 异常处理规范
- [ ] API 返回格式统一

---

### 2. 测试验证

- [ ] 单元测试通过
- [ ] 测试覆盖率达标（精简≥70%, 标准≥80%, 完整≥90%）
- [ ] API 测试通过（标准/完整流程）
- [ ] E2E 测试通过（完整流程）

---

### 3. 架构合规

- [ ] 未破坏现有架构
- [ ] 依赖关系合理
- [ ] 模块职责清晰

---

### 4. 度量指标（可选）

- [ ] KVC ≥ 0.90（如有）
- [ ] SCV < 5.0（如有）

---

## 输出

### 质量审查报告格式

```markdown
### 质量关卡报告

#### 代码规范
- Jackson 序列化: ✅
- 中文日志: ✅
- 无魔法值: ✅
- 异常处理: ✅
- API 格式: ✅

#### 测试验证
- 单元测试: ✅ 5/5 passed
- 覆盖率: ✅ 85%

#### 架构合规
- 架构完整性: ✅
- 依赖合理性: ✅

#### 综合评估
- 状态: ✅ PASS
- 可以提交代码
```

---

## 门禁决策

- **PASS** - 通过，可以提交代码
- **REJECT** - 不通过，需要修正后重新审查

---

## 何时执行

| 流程类型 | 是否必须 |
|---------|---------|
| 🟢 精简流程 | ✅ 必须 |
| 🟡 标准流程 | ✅ 必须 |
| 🔴 完整流程 | ✅ 必须 |

---

## 下一步

- PASS + 精简/标准流程 → 提交代码
- PASS + 完整流程 → `/archive`
- REJECT → 修正代码，重新运行相关步骤
