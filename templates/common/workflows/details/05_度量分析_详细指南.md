## KVC 度量详解

### 定义

**KVC (Key-Value Consistency)**: 键值一致性，衡量代码是否符合命名规约。

**公式**: `KVC = (符合规范的 Key 数量) / (总 Key 数量)`

**阈值**: `KVC ≥ 0.90` (90%)

### 规范说明

在算法编排项目中，Context Key 必须符合格式：
```
node:{nodeId}
```

**示例**:
- ✅ 正确: `context.put("node:timeOffset", value)`
- ❌ 错误: `context.put("offset", value)`
- ❌ 错误: `context.put("timeOffset", value)`

### 手动计算步骤

#### Step 1: 搜索所有 Context Key

```bash
# 搜索所有 context.put() 调用
grep -rn 'context\.put' src/main/java/ > /tmp/context_calls.txt

# 查看结果
cat /tmp/context_calls.txt
```

#### Step 2: 统计符合规范的 Key

创建统计表：

```markdown
| 文件 | 行号 | Key | 是否符合规范 | 备注 |
|------|------|-----|-------------|------|
| TimeOffsetCmp.java | 45 | "node:timeOffset" | ✅ | 符合 |
| TimeOffsetCmp.java | 52 | "node:result" | ✅ | 符合 |
| AnalogStatsCmp.java | 38 | "offset" | ❌ | 缺少 node: 前缀 |
| AnalogStatsCmp.java | 55 | "node:maxValue" | ✅ | 符合 |
```

#### Step 3: 计算 KVC

```
总 Key 数量: 4
符合规范: 3
违规: 1
KVC = 3 / 4 = 0.75 (75%)
```

#### Step 4: 判断是否达标

```markdown
### KVC 评估
- 计算值: 0.75
- 阈值: 0.90
- 状态: ❌ 未达标 (差距 15%)

#### 违规详情
1. AnalogStatsCmp.java:38
   - 当前: `context.put("offset", value)`
   - 应为: `context.put("node:offset", value)`
```

## SCV 度量详解

### 定义

**SCV (Structure Complexity Variation)**: 结构复杂度变化，衡量代码复杂度的突变程度。

**公式**: `SCV = |CC_current - CC_previous|`

**阈值**: `SCV < 5.0`

### 复杂度类型

#### 圈复杂度 (Cyclomatic Complexity)
- 衡量代码路径数量
- if/else/for/while 等分支增加复杂度
- **推荐**: 单个方法 ≤10

#### Radon 等级
- A: 1-5 (低复杂度) ✅
- B: 6-10 (中等复杂度) ⚠️
- C: 11-20 (高复杂度) 🔴
- D/E/F: >20 (极高复杂度) 🔴🔴

### 手动计算步骤

#### Step 1: 计算修改前的复杂度

如果是首次开发，复杂度基线为 0。

如果是修改现有代码：
```bash
# 使用 git 检出修改前的版本
git stash

# 计算复杂度（Python）
radon cc src/path/to/File.py -a

# 或计算复杂度（Java）
lizard src/main/java/path/to/File.java

# 记录输出
```

#### Step 2: 计算修改后的复杂度

```bash
# 恢复当前代码
git stash pop

# 计算当前复杂度
lizard src/main/java/com/etl/station/algo/operators/TimeOffsetCmp.java
```

**示例输出**:
```
NLOC CCN token PARAM length location
------ ------ ----- ----- ------ ------------------------------------------
  15    3     95    2     18     TimeOffsetCmp::process@45-62
   8    1     42    1     10     TimeOffsetCmp::validate@62-71
----------------------------------------------------------------
NLOC Avg.NLOC AvgCCN Avg.token function_cnt file
------ -------- ------ --------- ------------ -------
  23    11.5    2.0    68.5      2            TimeOffsetCmp.java
```

**解读**:
- 平均圈复杂度 (AvgCCN): 2.0
- process 方法复杂度: 3
- validate 方法复杂度: 1

#### Step 3: 计算 SCV

```markdown
### SCV 统计

#### 修改前（基线）
- 文件: TimeOffsetCmp.java
- 状态: 不存在（新文件）
- 复杂度: 0

#### 修改后（当前）
- 平均复杂度: 2.0
- 最高复杂度: 3 (process 方法)

#### SCV 计算
- CC_previous = 0 (新文件)
- CC_current = 2.0
- **SCV = |2.0 - 0| = 2.0**

### SCV 评估
- 计算值: 2.0
- 阈值: <5.0
- 状态: ✅ 正常
```

## 自动化脚本使用

### 快速开始

```bash
# 一键执行度量分析
python scripts/metrics.py .

# 输出位置:
# - .agent/metrics/report_<timestamp>.md
# - .agent/metrics/history.csv
```

### 脚本功能

1. **自动计算 KVC**
   - 扫描所有 `context.put()` 调用
   - 检查是否符合 `node:{nodeId}` 格式
   - 生成违规报告

2. **自动计算 SCV**
   - 使用 radon 计算圈复杂度
   - 对比修改前后的复杂度
   - 生成趋势分析

3. **生成报告**
   - Markdown 格式详细报告
   - CSV 格式历史数据
   - 自动追加到历史记录

### 输出示例

```

📊 计算 KVC（键值一致性）...
总 Key 数量: 45
符合规范: 42

KVC = 42 / 45 = 0.93
✅ KVC 达标 (≥ 0.90)

📊 计算 SCV（复杂度变化）...
```

## 手动计算方法

### 工具安装

#### Python 工具（推荐）

```bash
# 安装 radon（复杂度分析）
pip install radon

# 安装 lizard（多语言支持）
pip install lizard
```

#### Java 工具

```bash
# macOS
brew install pmccabe

# 或使用 Maven 插件
mvn pmd:pmd pmd:cpd
```

### radon 使用

```bash
# 计算单个文件复杂度
radon cc src/main/java/File.java -a

# 计算目录复杂度
radon cc src/main/java/ -a

# JSON 格式输出
radon cc src/main/java/ -a -j
```

### lizard 使用

```bash
# 分析单个文件
lizard src/main/java/File.java

# 分析整个目录
lizard src/main/java/

# 只显示复杂度 >10 的方法
lizard -C 10 src/main/java/
```

## 常见问题

### Q1: KVC 为什么重要？

**A**: 
- 统一的命名规范便于调试
- 减少 Key 冲突和覆盖
- 提高代码可维护性
- 便于自动化分析

### Q2: SCV 阈值为什么是 5.0？

**A**:
- 经验值：单次改动复杂度变化 <5 是健康的
- 超过 5 通常意味着引入了过多分支逻辑
- 需要考虑重构或简化

### Q3: 如何快速修复 KVC 违规？

**A**:
```bash
# 1. 找到违规位置
grep -rn 'context\.put("[^n]' src/

# 2. 批量替换（谨慎使用）
sed -i 's/context\.put("\([^"]*\)"/context.put("node:\1"/g' File.java

# 3. 验证
grep -rn 'context\.put' File.java
```

### Q4: 新文件的 SCV 总是等于当前复杂度，合理吗？

**A**:
- 是的，因为基线为 0
- 只要当前复杂度 <5，就算合理
- 重点关注平均复杂度和最高复杂度

### Q5: 度量分析要每次都做吗？

**A**:
- 精简流程：可跳过
- 标准流程：建议执行
- 完整流程：必须执行

### Q6: radon 和 lizard 有什么区别？

**A**:
- **radon**: 专注 Python，输出更详细
- **lizard**: 支持多语言（Java/C/Python），适合混合项目
- 建议：Java 项目用 lizard
