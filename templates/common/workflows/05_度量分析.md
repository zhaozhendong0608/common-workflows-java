# 度量分析

**命令**: `/measure`

---

## 输入

- 代码变更（来自 `/execute`）
- 项目根目录

---

## 核心步骤

### 方案1: 自动化脚本（推荐）⭐

**一键执行度量分析**:
```bash
python scripts/metrics.py .
```

**输出位置**:
- `.agent/metrics/report_<timestamp>.md` - 详细报告
- `.agent/metrics/history.csv` - 历史数据

---

### 方案2: 手动计算

如果无法使用脚本，手动执行以下步骤：

**1. 计算 KVC（键值一致性）**
```bash
# 搜索所有 context.put() 调用
grep -rn 'context\.put' src/ > /tmp/context_calls.txt
```

统计符合 `node:{nodeId}` 规范的比例：
- KVC = (符合规范的 Key 数量) / (总 Key 数量)
- **阈值**: KVC ≥ 0.90

**2. 计算 SCV（复杂度变化）**
```bash
# 安装工具
pip install radon lizard

# 计算圈复杂度
lizard src/main/java/path/to/File.java
```

- SCV = |CC_current - CC_previous|
- **阈值**: SCV < 5.0

📖 [查看详细度量指南](./details/05_度量分析_详细指南.md)

---

## 输出

### 度量报告格式

```markdown
### 质量度量报告

#### KVC (键值一致性)
- 总 Key 数量: 4
- 符合规范: 3
- KVC = 0.75 (75%)
- 状态: ❌ 未达标 (阈值 ≥0.90)

#### SCV (复杂度变化)
- 修改前: 0 (新文件)
- 修改后: 2.0
- SCV = 2.0
- 状态: ✅ 正常 (阈值 <5.0)

#### 综合评估
- KVC: ❌ 未达标
- SCV: ✅ 正常
- 总体: ⚠️ 需要修正
```

---

## 度量指标说明

| 指标 | 定义 | 阈值 | 说明 |
|------|------|------|------|
| **KVC** | 键值一致性 | ≥0.90 | Context Key 命名规范符合度 |
| **SCV** | 复杂度变化 | <5.0 | 代码复杂度稳定性 |

---

## 下一步

- KVC ≥ 0.90 且 SCV < 5.0 → `/test`
- KVC < 0.90 → 修正代码，重新运行 `/measure`
- SCV ≥ 5.0 → 重构代码，降低复杂度
