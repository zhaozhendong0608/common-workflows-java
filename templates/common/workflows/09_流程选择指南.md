# 流程选择指南

**用途**: 帮助你快速选择合适的工作流类型

---

## 快速决策

### 问题1: 任务复杂度

- **简单**（改字段、加校验、修文案） → 🟢 精简流程
- **中等**（新增API、修改逻辑、业务功能） → 🟡 标准流程
- **复杂**（重构模块、架构变更、技术决策） → 🔴 完整流程

---

### 问题2: 涉及文件数量

- **1-3 个文件** → 🟢 精简流程
- **4-10 个文件** → 🟡 标准流程
- **10+ 个文件** → 🔴 完整流程

---

### 问题3: 是否有架构变更

- **无架构变更** → 🟢/🟡
- **有架构变更** → 🔴 完整流程

---

## 三种流程对比

| 维度 | 🟢 精简流程 | 🟡 标准流程 | 🔴 完整流程 |
|------|-----------|-----------|-----------|
| **耗时** | 30 min | 60 min | 93 min |
| **步骤** | 4 步 | 7 步 | 9 步 |
| **Evidence** | 5 字段 | 10 字段 | 20 字段 |
| **测试要求** | 单元测试 | + API 测试 | + E2E 测试 |
| **适用场景** | 小改动 | 新功能 | 重构/架构 |

---

## 流程步骤

### 🟢 精简流程（30分钟）
```
/boot → /radar → /execute → /quality
```

### 🟡 标准流程（60分钟）
```
/boot → /constraint → /radar → /execute → /measure → /test → /quality
```

### 🔴 完整流程（93分钟）
```
/boot → /constraint → /radar → /execute → /measure → /test → /quality → /archive
```

## 典型案例

### 案例1: 添加字段
**需求**: User 表增加 email 字段
**选择**: 🟢 精简流程
**理由**: 只涉及 1 个 Entity + 1 个 SQL，无架构变更

### 案例2: 新增导出功能
**需求**: 用户列表导出为 Excel
**选择**: 🟡 标准流程
**理由**: 涉及 Controller + Service + Mapper，需要 API 测试

### 案例3: 引入缓存层
**需求**: 重构 Service 层，添加 Caffeine 缓存
**选择**: 🔴 完整流程
**理由**: 架构变更，需要记录 ADR，完整测试
