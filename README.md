## 简介

这是一套适用于 **Java 项目** 的通用开发工作流标准，包含：

✅ **工作流**: 9 步标准开发流程 + **智能分流机制**（新增）
✅ **内核模板**: 项目知识管理体系
✅ **示例**: 实战开发指南
✅ **脚本**: 自动化工具（可选）

### 🆕 v1.1 新特性：智能分流

根据任务规模自动建议流程类型，避免"杀鸡用牛刀"：
- 🟢 **精简流程** (30 min)：改字段、加校验
- 🟡 **标准流程** (60 min)：新增功能、修改逻辑
- 🔴 **完整流程** (93 min)：重构模块、架构变更

📊 **架构图**: [查看完整的智能分流架构图](./docs/architecture/智能分流架构图.md)（含 6 个 Mermaid 图表）

## 核心价值

### 1. 约束显式化
- 从"AI 隐式记忆"变为"YAML 清单"
- 防止 AI 遗忘或曲解规范
- 人工检查清单逐项验证

### 2. 质量量化
- KVC (键值一致性) ≥ 0.90
- SCV (复杂度变化) < 5.0
- 历史数据可追踪

### 3. 业务测试完善
- API 集成测试（100% 自动化）
- E2E 端到端测试（80% 自动化）
- UI/UX 人工测试清单

### 4. 知识积累
- 架构决策记录（ADR）
- 技术问题库（FAQ）
- 项目进度追踪
- 度量数据归档

## 快速开始

### Step 1: 创建新项目

```bash
# 1. 创建项目目录
mkdir my-project && cd my-project

# 2. 初始化 Git
git init
```

### Step 2: 复制工作流

```bash
# 3. 复制工作流文件
mkdir -p .agent
cp -r /path/to/common-workflows-java/workflows .agent/
```

### Step 3: 初始化项目内核

```bash
# 4. 复制内核模板
mkdir -p project-kernel
cp -r /path/to/common-workflows-java/kernel-template/* project-kernel/
```

### Step 4: 定制项目内核

```bash
# 5. 编辑项目信息
cd project-kernel

# 编辑 00_系统总纲.md，填充项目名称、技术栈等
# 编辑 01_项目全景.md，描述模块划分
# 02_开发规约/ 可直接使用（Java 通用规范）
# 03-06 根据项目实际情况记录
```

### Step 5: 准备度量环境

```bash
# 6. 安装度量工具
pip install radon lizard

# 7. 创建度量目录
mkdir -p .agent/metrics/reports
echo "date,module,kvc,scv,coverage,status" > .agent/metrics/history.csv
```

### Step 6: 开始开发

按照工作流开发即可：

```
01_启动自检
 ↓
02_需求雷达
 ↓
03_规约形式化
 ↓
04_受控执行
 ↓
05_度量分析
 ↓
06_业务测试
 ↓
07_质量关卡
 ↓
08_归档重启
```

## 常见问题 (FAQ)

### Q1: 内核目录必须叫 project-kernel 吗？

**A**: 不必须，可以改为：
- `docs/project-standards/`
- `.project/kernel/`
- 任何你喜欢的名字

**但需要**：在工作流文件中全局替换 `project-kernel` 为你的目录名

```bash
cd .agent/workflows
sed -i '' 's/project-kernel/your-dir-name/g' *.md
```

---

### Q2: 如何选择合适的流程？

**A**: 参考智能分流建议，或查看 [流程选择指南](./workflows/09_流程选择指南.md)

**快速判断**:
- 改 1-2 个文件，≤ 50 行代码 → 🟢 精简流程 (ACK-LITE)
- 改 3-5 个文件，≤ 150 行代码 → 🟡 标准流程 (ACK)
- 改 > 5 个文件，或触碰 Solid 资产 → 🔴 完整流程 (ACK-FULL)

---

### Q3: 如何在已有项目中使用？

**A**:
1. 先创建内核目录，填充 00_系统总纲 和 01_项目全景
2. 反向工程：从现有代码提取约束清单
3. 从下次开发任务开始使用工作流

参考：`examples/接手已有项目指南.md`（v1.2.0 计划）

---

### Q4: 工作流文件可以修改吗？

**A**:
- ✅ 可以调整阈值（KVC/SCV）
- ✅ 可以增加项目特定检查
- ⚠️ 不建议修改核心流程
- ❌ 不建议删除 Evidence Block

---

### Q5: 精简流程会降低质量吗？

**A**: 不会。精简流程仍然保证：
- ✅ P0 约束检查（强制）
- ✅ 单元测试通过（必须）
- ✅ Evidence Block（简化但完整）
- ✅ 质量关卡（人工审查）

只是跳过了对小改动"性价比低"的步骤（度量分析、业务测试、ADR 归档）。

---

### Q6: 如何查看度量历史？

**A**: 度量数据保存在 `.agent/metrics/history.csv`

```bash
# 查看最近 10 条记录
tail -10 .agent/metrics/history.csv

# 使用 Excel/Numbers 打开
open .agent/metrics/history.csv
```

## 完整工作流说明

### 🆕 智能分流机制

从 v1.1 版本开始，工作流支持**自动分流**，根据任务规模智能建议流程类型：

| 流程类型 | 预计时间 | 适用场景 | 关键字 |
|---------|---------|---------|--------|
| 🟢 精简流程 | 30 min | 改字段、加校验、修常量 | ACK-LITE |
| 🟡 标准流程 | 60 min | 新增功能、修改逻辑 | ACK |
| 🔴 完整流程 | 93 min | 重构模块、架构变更 | ACK-FULL |

**工作原理**: 在 `/03_需求雷达` 完成后，AI 会根据以下维度自动评分：
- 文件数量（权重 30%）
- 代码行数（权重 25%）
- Pizza 切片（权重 20%）
- Solid 触碰（权重 15%）
- 风险等级（权重 10%）

详见：[workflows/09_流程选择指南.md](./workflows/09_流程选择指南.md)

---

### 01_启动自检 (5 min)
- 加载项目内核
- 理解技术栈和架构
- 自信心评分

### 02_需求雷达 (10 min)
- 分析需求范围
- 识别依赖关系
- Pizza 切片判定
- **🆕 智能分流建议**

### 03_规约形式化 (10 min) Level 1
- 提取约束清单
- 生成检查清单
- 预测 FSM 状态序列

### 04_受控执行 (25 min)
- 原子化执行
- **🆕 多级 Evidence Block**（简化版/标准版/完整版）
- 约束实时检查

### 05_度量分析 (10 min) Level 1
- 计算 KVC（键值一致性）
- 计算 SCV（复杂度变化）
- 生成度量报告

### 06_业务测试 (20 min) Level 1
- API 集成测试
- E2E 端到端测试
- UI/UX 人工测试

### 07_质量关卡 (5 min)
- Evidence 审计
- 度量指标审查
- ADR 合规性检查

### 08_归档重启 (8 min)
- 同步 ADR、FAQ、进度
- 归档度量数据
- 物理重启会话

**实际耗时**:
- 精简流程：30 分钟/功能
- 标准流程：60 分钟/功能
- 完整流程：93 分钟/功能

## 核心概念

### KVC - 键值一致性

**定义**: 衡量代码中的键值对是否符合项目规范

**公式**: `KVC = (符合规范的 Key 数量) / (总 Key 数量)`

**阈值**: `≥ 0.90` (90%)

**适用场景**: 项目有特定的 Key 命名规范时

---

### SCV - 结构复杂度变化

**定义**: 衡量代码圈复杂度的变化幅度

**公式**: `SCV = |CC_current - CC_previous|`

**阈值**: `< 5.0`

**适用场景**: 所有代码修改

---

### Evidence Block

每次执行必须产出的证据：

```markdown
### Context Evidence
- **Compliance_Status**: /⚠️/🔴
- **Target_Files**: [...]
- **Test_Run**: [命令 + 结果]
- **Constraint_Check**: P0 违规数
```

## 质量标准

### 代码质量

| 指标 | 阈值 | 说明 |
|------|------|------|
| 测试覆盖率 | >80% | 单元测试 + 集成测试 |
| 圈复杂度 | <10 | 单个方法 |
| KVC | ≥0.90 | 键值一致性（如适用）|
| SCV | <5.0 | 复杂度变化 |

### 质量评级

- **S 级**: 所有指标优秀
- **A 级**: 核心指标达标
- **B 级**: 基本达标，有改进空间
- **C 级**: 不达标，需返工
