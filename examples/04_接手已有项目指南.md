# 接手已有项目指南

本指南说明如何在已有项目中应用工作流标准。

## 📋 适用场景

- ✅ 接手他人的项目
- ✅ 为现有项目引入工作流
- ✅ 团队推广工作流标准
- ✅ 外包项目质量管控

---

## 🚀 快速开始（3 步骤）

### Step 1: 初始化项目内核 (20 min)

```bash
# 1. 进入项目根目录
cd /path/to/existing-project

# 2. 创建 .agent 目录
mkdir -p .agent/{metrics,constraint}

# 3. 复制 kernel-template 到项目
cp -r /path/to/common-workflows-java/kernel-template ./kernel-template

# 4. 初始化 Git（如果还没有）
git init
git add .
git commit -m "chore: 初始化项目结构"
```

---

### Step 2: 理解项目现状 (30 min)

**执行启动自检**:
```
向 AI: 请执行 01_启动自检.md
目标项目: /path/to/existing-project
```

**AI 会分析**:
- 📊 项目技术栈（Spring Boot 版本、Java 版本等）
- 📂 目录结构（是否符合规范）
- 📄 现有文档（README、架构文档等）
- ⚙️ 配置文件（application.yml、pom.xml 等）
- 🧪 测试覆盖率（是否有测试）

**预期输出**:
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 项目全景分析
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 技术栈识别
  - Spring Boot: 2.7.5
  - Java: 11
  - MyBatis: 3.5.10
  - MySQL: 8.0

⚠️  发现的问题
  - 缺少单元测试（覆盖率 0%）
  - 没有架构文档
  - 命名不规范（部分文件）
  - 缺少注释

📋 建议改进项
  1. 补充单元测试（优先级：高）
  2. 编写架构文档（优先级：高）
  3. 统一命名规范（优先级：中）
  4. 添加代码注释（优先级：中）

信心评分: 65/100 (可以开始，但需谨慎)
```

---

### Step 3: 填充项目内核 (40 min)

#### 3.1 编写架构规约

**创建**: `kernel-template/01_架构规约/01_技术栈.md`

```markdown
# 技术栈说明

## 核心框架
- **Spring Boot**: 2.7.5
- **MyBatis**: 3.5.10
- **MySQL**: 8.0

## 架构模式
- MVC 三层架构
- RESTful API

## 目录结构
- src/main/java/com/example/
  - controller/ (控制层)
  - service/ (业务层)
  - mapper/ (数据层)
  - entity/ (实体类)
  - dto/ (数据传输对象)
```

---

#### 3.2 记录开发规约

**创建**: `kernel-template/02_开发规约/01_编码规范.md`

```markdown
# 编码规范

## P0 约束（强制）
1. Controller 必须使用 @RestController
2. 返回值必须包装为 Result<T>
3. Service 必须添加 @Transactional

## P1 约束（建议）
1. 方法需要添加注释
2. 变量使用驼峰命名

## P2 约束（可选）
1. 使用 Google Java Style
```

---

#### 3.3 记录已有决策

**创建**: `kernel-template/03_决策日志/ADR-001-技术栈选择.md`

```markdown
# ADR-001: 技术栈选择

**状态**: 已接受
**日期**: {项目创建时间}
**决策者**: {原团队}

## 背景
项目需要快速开发 RESTful API

## 决策
采用 Spring Boot + MyBatis + MySQL

## 理由
- Spring Boot: 快速启动
- MyBatis: 灵活的 SQL 控制
- MySQL: 成熟稳定
```

## 🎯 渐进式改进策略

### 策略 1: 新代码高标准 + 老代码保持（推荐）⭐

**原则**:
- ✅ 新功能：严格遵守工作流
- ✅ Bug 修复：修改部分应用工作流
- ⚠️  老代码：暂不强制改造

**优势**:
- 不影响现有功能
- 逐步提高代码质量
- 团队容易接受

**实施**:
```bash
# 在 Git 提交信息中标记
git commit -m "feat: 新增用户管理功能

[工作流] 标准流程 (60 min)
- Evidence: Pass
- KVC: 0.95
- 测试覆盖率: 88%
"
```

---

### 策略 2: 分模块重构（适合有时间）

**步骤**:
1. 识别核心模块（用户、订单等）
2. 按模块优先级排序
3. 逐个模块应用工作流重构
4. 每个模块生成独立的 Evidence

**示例时间线**:
```
Week 1-2: 用户模块重构
Week 3-4: 订单模块重构
Week 5-6: 支付模块重构
...
```

---

### 策略 3: 双仓库对比（适合外包）

**场景**: 接手外包代码，质量堪忧

**步骤**:
1. 保留原仓库（只读）
2. 创建新仓库
3. 按工作流重写核心模块
4. 对比质量差异

**对比维度**:
| 维度 | 原仓库 | 新仓库（工作流） |
|------|--------|-----------------|
| 测试覆盖率 | 0% | 85% |
| KVC | 0.32 | 0.94 |
| SCV | 12.5 | 3.2 |
| 文档完整度 | 20% | 90% |

## 🔧 常见问题处理

### Q1: 项目没有测试怎么办？

**A**: 分阶段补充测试

**Phase 1**: 核心功能测试
```java
// 先写最关键的测试
@Test
void testUserLogin() {
    // 登录功能测试
}

@Test
void testOrderCreate() {
    // 订单创建测试
}
```

**Phase 2**: 边界测试
```java
@Test
void testUserLoginWithInvalidPassword() {
    // 异常场景测试
}
```

**Phase 3**: 集成测试
```java
@SpringBootTest
class UserIntegrationTest {
    // 端到端测试
}
```

---

### Q2: 代码规范混乱怎么办？

**A**: 使用工具批量格式化

```bash
# 1. 安装 Google Java Format
brew install google-java-format

# 2. 批量格式化
find src -name "*.java" | xargs google-java-format -i

# 3. 提交
git commit -m "style: 统一代码格式"
```

---

### Q3: 没有文档怎么办？

**A**: 使用 AI 辅助生成初版

```
向 AI: 请分析项目并生成架构文档

目标: kernel-template/01_架构规约/02_系统架构.md

AI 会:
1. 扫描代码结构
2. 识别模块关系
3. 生成架构图
4. 编写文档初稿
```

**然后人工审查和完善**

---

### Q4: 团队抵触怎么办？

**A**: 渐进式推广

**Week 1**: 个人使用
- 自己的新功能严格遵守
- 记录效果（时间、质量）

**Week 2**: 小范围试点
- 1-2 位同事参与
- 收集反馈

**Week 3**: 团队评审
- 展示效果对比
- 讨论调整方案

**Week 4**: 全面推广
- 团队达成共识
- 统一执行标准

## 🎯 成功案例

### 案例 1: 接手外包项目

**背景**:
- 外包团队交付代码质量差
- 无测试、无文档、无规范
- 需要快速接手并维护

**实施**:
1. Week 1: 初始化项目内核 + 生成基线报告
2. Week 2-3: 核心模块补充测试
3. Week 4-5: 按工作流重构关键功能
4. Week 6: 团队培训 + 推广

**效果**:
- 测试覆盖率：0% → 75%
- KVC：0.28 → 0.91
- SCV：15.3 → 4.2
- Bug 率：下降 60%

---

### 案例 2: 团队推广工作流

**背景**:
- 团队 5 人，各自风格不同
- 代码审查困难
- 质量不稳定

**实施**:
1. Week 1: 个人试点（1 人）
2. Week 2: 小组试点（3 人）
3. Week 3: 团队评审 + 调整
4. Week 4: 全员推广

**效果**:
- 代码风格统一
- PR 审查时间：2 小时 → 30 分钟
- 返工率：下降 40%
